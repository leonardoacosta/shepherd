Shepherd detects supported agents automatically. Official integrations can add native session identity for restore, lifecycle state reports, or both.

Use integrations when you want native agent session restore from Claude Code/Codex/Copilot/Devin-style hooks, direct lifecycle reports from Pi/OMP/Kimi/OpenCode/Kilo/Hermes-style hooks or plugins, or both. See [Agents](/docs/agents/) for the full status authority model.

## Install integrations

Open settings inside Shepherd and use the integrations tab to install recommended integrations for agents found on your `PATH`, or run commands manually:

```bash
shepherd integration install pi
shepherd integration install omp
shepherd integration install claude
shepherd integration install codex
shepherd integration install copilot
shepherd integration install devin
shepherd integration install droid
shepherd integration install kimi
shepherd integration install opencode
shepherd integration install kilo
shepherd integration install hermes
shepherd integration install qodercli
shepherd integration install cursor
shepherd integration install mastracode
shepherd integration install grok
```

## How Shepherd uses integrations

Shepherd uses integrations in two different ways:

| Integration type | Agents | Effect |
| --- | --- | --- |
| Lifecycle authority | Pi, OMP, Kimi Code CLI, OpenCode, Kilo Code CLI, Hermes Agent, MastraCode | When installed and actively reporting for the pane, hook or plugin events author `idle`, `working`, and `blocked`. Shepherd does not also use screen manifest fallback for that same lifecycle authority. |
| Session identity | Claude Code, Codex, GitHub Copilot CLI, Devin CLI, Droid, Qoder CLI, Cursor Agent CLI, Grok CLI | The integration reports native session references for restore. State still comes from Shepherd's screen manifest detection. |

Custom socket integrations can also report state when they define state that is not visible in the native terminal UI.

Some integrations report native agent session references. Shepherd uses official session references to resume Claude Code, Codex, Devin CLI, Droid, Kimi Code CLI, Qoder CLI, Cursor Agent CLI, Grok CLI, GitHub Copilot CLI, Pi, OMP, Hermes Agent, OpenCode, Kilo Code CLI, and MastraCode panes after a Shepherd server restart unless `[session] resume_agents_on_restore = false` disables it.

Native session restore requires current Shepherd integrations: Pi integration version `2`, OMP version `3`, Claude Code version `6`, Codex version `5`, GitHub Copilot CLI version `2`, Devin CLI version `2`, Droid version `2`, Kimi Code CLI version `3`, Qoder CLI version `2`, Cursor Agent CLI version `1`, Grok CLI version `1`, OpenCode version `5`, Kilo Code CLI version `1`, Hermes Agent version `2`, or MastraCode version `1`. Check installed versions with `shepherd integration status`.

## Pi

Install the Pi integration:

```bash
shepherd integration install pi
```

Shepherd writes the bundled extension to:

```text
~/.pi/agent/extensions/shepherd-agent-state.ts
```

If `PI_CODING_AGENT_DIR` is set, Shepherd writes to `$PI_CODING_AGENT_DIR/extensions/shepherd-agent-state.ts` instead. Shepherd creates the extensions directory when the Pi agent directory already exists. Uninstall removes only that extension file.

## OMP

Install the OMP integration:

```bash
shepherd integration install omp
```

Shepherd writes the bundled extension to:

```text
~/.omp/agent/extensions/shepherd-omp-agent-state.ts
```

Shepherd uses `PI_CODING_AGENT_DIR` as the complete agent directory when set. Otherwise, it uses `$HOME/$PI_CONFIG_DIR/agent` when `PI_CONFIG_DIR` is set, falling back to `~/.omp/agent`. If Pi and OMP resolve to the same extension directory, Shepherd refuses the OMP install so the OMP extension cannot be loaded by Pi. Configure separate agent directories before installing both integrations. Shepherd creates the extensions directory when the resolved OMP agent directory already exists. Uninstall removes only that extension file.

The OMP integration reports `omp` as the agent label, lifecycle state, and native session identity through Shepherd's socket API. It does not require native process detection for the `omp` executable, and Shepherd can resume an OMP pane with `omp --resume=<session>` after a server restart.

## Claude Code

Install the Claude Code hook:

```bash
shepherd integration install claude
```

The hook reports Claude Code session identity to the local Shepherd socket on session start. Claude Code state comes from Shepherd's screen manifest detection.

Shepherd uses `~/.claude` by default, or `CLAUDE_CONFIG_DIR` when set. The Claude config directory must already exist. Install writes `hooks/shepherd-agent-state.sh` and updates `settings.json` with Shepherd hook entries. Uninstall removes the matching hook entries and deletes the hook script.

## Codex

Install the Codex hook:

```bash
shepherd integration install codex
```

The Codex hook reports session identity through the same local socket API used by other integrations. Codex state comes from Shepherd's screen manifest detection.

Shepherd uses `~/.codex` by default, or `CODEX_HOME` when set. The Codex config directory must already exist. Install writes `shepherd-agent-state.sh`, updates `hooks.json`, and ensures `[features] hooks = true` in `config.toml`. It also removes the deprecated top-level `codex_hooks` flag when present. Uninstall removes Shepherd entries from `hooks.json` and deletes the hook script, but leaves `config.toml` unchanged.

## GitHub Copilot CLI

Install the GitHub Copilot CLI hook:

```bash
shepherd integration install copilot
```

The Copilot hook reports session identity through the same local socket API used by other integrations. Copilot state comes from Shepherd's screen manifest detection.

Shepherd uses `~/.copilot` by default, or `COPILOT_HOME` when set. The Copilot config directory must already exist. Install writes `hooks/shepherd-agent-state.sh` and updates `settings.json` with a `SessionStart` hook entry. Uninstall removes Shepherd entries from `settings.json` and deletes the hook script.

## Devin CLI

Install the Devin CLI hook:

```bash
shepherd integration install devin
```

The hook reports native session identity from Devin session, prompt, tool-use, permission, and stop events. Devin state still comes from Shepherd's screen manifest and OSC detection because Devin hooks do not emit a reliable state transition after every permission cancellation or user interrupt.

Shepherd uses `~/.config/devin` by default, or `$XDG_CONFIG_HOME/devin` when `XDG_CONFIG_HOME` is set. The Devin config directory must already exist. Install writes `shepherd-agent-state.sh` and updates `config.json` with Shepherd hook entries. The hook refreshes the session reference while Devin runs. Uninstall removes Shepherd entries from `config.json` and deletes the hook script.

Shepherd resumes stored Devin sessions with `devin --resume <id>`. Native screen manifest detection remains the state authority whether or not the hook is installed.

## Kimi Code CLI

Install the Kimi Code CLI hook:

```bash
shepherd integration install kimi
```

The hook reports Kimi session identity and lifecycle state to Shepherd for native restore and authoritative `idle`, `working`, and `blocked` status. It requires Kimi Code CLI `0.14.0` or newer.

Shepherd uses `~/.kimi-code` by default, or `KIMI_CODE_HOME` when set. The Kimi Code config directory must already exist. Install writes `hooks/shepherd-agent-state.sh` and appends Shepherd-managed `[[hooks]]` entries to `config.toml`. Uninstall removes the Shepherd-managed config block and deletes the hook script.

Shepherd resumes stored Kimi sessions with `kimi --session <id>`.

## Droid

Install the Droid hook:

```bash
shepherd integration install droid
```

The Droid hook reports session identity through the same local socket API used by other integrations. Lifecycle state still comes from Shepherd's screen manifest detection because Droid hooks do not cover every lifecycle transition.

Shepherd uses `~/.factory` for Droid hooks. The Factory config directory must already exist. Install writes `hooks/shepherd-agent-state.sh`, updates `settings.json` with a Shepherd `SessionStart` hook entry, and removes older Shepherd Droid hook entries from `hooks.json` if present. Uninstall removes Shepherd entries from both config files and deletes the hook script.

After Droid emits a session start event, Shepherd can use the reported session id to resume the pane with `droid --resume <id>`.

## Hermes Agent

Install the Hermes Agent plugin:

```bash
shepherd integration install hermes
```

Shepherd writes `~/.hermes/plugins/shepherd-agent-state/` and enables `shepherd-agent-state` in `~/.hermes/config.yaml`. The Hermes config directory must already exist. Restart Hermes after installing so the plugin loads. Uninstall removes the plugin directory and removes `shepherd-agent-state` from `plugins.enabled`.

The plugin reports lifecycle, tool, approval state, and session id while Hermes runs inside a Shepherd pane. Shepherd can use the reported session id to resume the pane with `hermes --resume <id>`. Native screen manifest detection remains available when the plugin is not installed.

## Cursor Agent CLI

Install the Cursor Agent CLI hook:

```bash
shepherd integration install cursor
```

The hook reports session identity through Cursor's `sessionStart` hook while Cursor Agent CLI runs inside a Shepherd pane. Cursor state comes from Shepherd's screen manifest detection.

Shepherd uses `~/.cursor` by default, or `CURSOR_CONFIG_DIR` when set. The Cursor config directory must already exist. Install writes `shepherd-agent-state.sh` and adds a Shepherd `sessionStart` entry to `hooks.json`. Uninstall removes the matching hook entry and deletes the hook script.

After Cursor emits a session start event, Shepherd can use the reported session id to resume the pane with `cursor-agent --resume <id>`. The `cursor-agent` command must be on `PATH` when Shepherd restores the pane; Shepherd does not launch the generic `agent` command.

## MastraCode

Install the MastraCode hook:

```bash
shepherd integration install mastracode
```

The hook reports MastraCode lifecycle state and thread identity to Shepherd for authoritative `idle`, `working`, and `blocked` status and native restore. MastraCode has no screen manifest fallback; state comes from the hook while MastraCode runs inside a Shepherd pane.

Shepherd uses `~/.mastracode`. Install writes `hooks/shepherd-agent-state.sh` and adds Shepherd command entries to `hooks.json`, creating the directory when missing. Uninstall removes the matching hook entries and deletes the hook script.

Shepherd resumes stored MastraCode threads with `mastracode --thread <id>`.

## Grok CLI

Install the Grok CLI hook:

```bash
shepherd integration install grok
```

The hook reports session identity through Grok's `SessionStart` hook while Grok CLI runs inside a Shepherd pane. Grok state comes from Shepherd's screen manifest detection.

Shepherd uses `~/.grok` by default, or `GROK_HOME` when set. The Grok config directory must already exist. Grok merges every `hooks/*.json` file in that directory, so install writes a self-contained `hooks/shepherd.json` with the Shepherd `SessionStart` entry next to the `hooks/shepherd-agent-state.sh` script, and never edits other hook files. Uninstall removes exactly those two Shepherd-owned files.

After Grok emits a session start event, Shepherd can use the reported session id to resume the pane with `grok --resume <id>`.

## Custom status labels

Integrations report lifecycle state as semantic state only. For example, report an agent as `working` without adding display fields to the lifecycle report.

```bash
shepherd pane report-agent w1:p1 \
  --source custom:docs \
  --agent docs-bot \
  --state working
```

User hooks that run next to a Shepherd-managed integration should use metadata instead of `report-agent`. Metadata changes presentation without taking over the integration's `idle`, `working`, `blocked`, or session restore authority. `--agent` and `--applies-to-source` guard only presentation fields (`--title`, `--display-agent`, and `--state-label`). Token patches always apply; their reporter owns clearing or TTL refresh. `--display-agent` changes the visible name.

```bash
shepherd pane report-metadata "$SHEPHERD_PANE_ID" \
  --source user:claude-title \
  --agent claude \
  --title "Refactor auth middleware" \
  --display-agent "Claude: auth" \
  --token summary="refactor auth" \
  --state-label working="refactoring auth" \
  --ttl-ms 3600000
```

Tokens and state labels are visual-only. Waits, notifications, and workspace rollups still use the semantic state.

## Debug integration state

List known agents:

```bash
shepherd agent list
```

Read a pane when you need to verify what Shepherd can see:

```bash
shepherd pane read w1:p1 --source recent --lines 50
```

If integration state looks wrong, first confirm the agent is running inside Shepherd and that the relevant hook or plugin was installed for the same user account.
