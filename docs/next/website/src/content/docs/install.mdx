Shepherd is source-built during the private product cutover. No Shepherd binary,
Homebrew, mise, or Windows release is published yet. On managed homelab and Mac hosts,
install or update the runtime and native plugins with:

```bash
shepherd-install --update
```

The release-channel commands below are staged for the first Shepherd product release;
they are not available during cutover.

## Planned direct install

On Linux or macOS, run:

```bash
curl -fsSL https://shepherd.dev/install.sh | sh
```

On Windows preview beta, install the preview channel:

```powershell
powershell -ExecutionPolicy Bypass -c "irm https://shepherd.dev/install.ps1 | iex"
```

The installer downloads the right release binary for your platform and places it on your PATH. Shepherd defaults to preview on Windows without changing your config. The installer uses versioned install folders and updates a `current` junction, so updates do not need to overwrite a running `shepherd.exe`.

## Install with Homebrew

If you already use Homebrew:

```bash
brew install shepherd
```

## Install with mise

If you already use mise:

```bash
mise use -g shepherd
```

If mise reports `shepherd not found in mise tool registry`, update mise and retry. Older mise versions predate the Shepherd registry entry; `mise use -g github:leonardoacosta/shepherd` works as a temporary fallback.

## Install with Nix

If you already use Nix, Shepherd provides a flake that builds Shepherd from source:

```bash
nix run github:leonardoacosta/shepherd/v0.x.y
nix build github:leonardoacosta/shepherd/v0.x.y
nix profile install github:leonardoacosta/shepherd/v0.x.y
```

Replace `v0.x.y` with the latest release tag. You can omit the tag to track `master`, but release tags are recommended for normal installs.

The flake also exposes a development shell:

```bash
nix develop github:leonardoacosta/shepherd
```

Update through the same Nix workflow you used to install Shepherd. For a profile install, list your profile entries and upgrade the Shepherd entry:

```bash
nix profile list
nix profile upgrade <index-or-name>
```

If Shepherd is an input in your own flake, update that input and rebuild your system, Home Manager, or development environment:

```bash
nix flake update shepherd
```

## Download manually

You can also download a binary from [GitHub releases](https://github.com/leonardoacosta/shepherd/releases).

Choose the asset that matches your system:

| System | Asset |
| --- | --- |
| Linux x86_64 | `shepherd-linux-x86_64` |
| Linux aarch64 | `shepherd-linux-aarch64` |
| macOS Intel | `shepherd-macos-x86_64` |
| macOS Apple silicon | `shepherd-macos-aarch64` |

On Linux or macOS, make it executable and move it somewhere on your PATH.

```bash
chmod +x shepherd-linux-x86_64
mv shepherd-linux-x86_64 ~/.local/bin/shepherd
```

### Windows beta downloads

Windows binaries are published only on preview releases while native Windows support is in beta. Use the preview installer above for normal testing, or download the Windows asset from a preview GitHub prerelease:

| System | Asset |
| --- | --- |
| Windows x86_64 beta | `shepherd-windows-x86_64.zip` |

The archive contains `shepherd.exe` and its app-local ConPTY runtime. Keep the extracted directory together; do not copy only `shepherd.exe`.

## Verify

Start Shepherd:

```bash
shepherd
```

If your shell cannot find `shepherd`, restart the terminal or check that the install directory is on your PATH.

## Update

Shepherd checks for new releases and notifies you in the app. You can update manually:

```bash
shepherd update
```

`shepherd update` is for installs managed by Shepherd's own installer. Homebrew, mise, and Nix installs are updated through those package managers instead.

On Linux and macOS, Shepherd uses the stable update channel by default. To opt into preview builds from `master`, set the channel:

```bash
shepherd channel set preview
```

Switch Linux and macOS direct installs back to stable the same way:

```bash
shepherd channel set stable
```

For direct installs, changing channels also checks that channel and installs its latest binary. If that update fails, run `shepherd update` to retry from the configured channel.

Preview builds are manually published GitHub prereleases from the current development branch. They are useful when you want fixes before the next stable release, but they can regress. Homebrew, mise, and Nix installs do not use the preview channel.

Windows beta builds are preview-only for now. `shepherd channel set stable` is rejected on Windows until stable Windows releases are available.

By default, `shepherd update` installs the new binary and leaves compatible running sessions alone. If an update changes Shepherd's client/server protocol, Shepherd asks whether to stop the old server after installing. Stop the old server to use the new version. Stopping exits pane processes. For the default session, run `shepherd server stop`, then run `shepherd` again. For a named session, run `shepherd session stop <name>`, then run `shepherd session attach <name>` again.

To opt into experimental live server handoff for supported running sessions, run:

```bash
shepherd update --handoff
```

Live handoff does not apply to Homebrew, mise, or Nix package-manager updates. For those installs, update with the package manager, then restart that Shepherd session when you are ready to use the new server. If a running session still uses the old server, stop it with `shepherd server stop` or `shepherd session stop <name>`, then run Shepherd again.

## Requirements

Stable Shepherd releases support Linux and macOS. Native Windows builds are preview-only beta releases; see [Windows beta](/docs/windows-beta/) for supported workflows and known limitations.
