Shepherd はペインをバックグラウンドサーバーで動かし続けます。ターミナルクライアントはデタッチして、あとで再接続できます。

ローカル、SSH、`shepherd --remote` の各ワークフローについては [Shepherd での作業の進め方](/ja/docs/how-to-work/)を参照してください。

## デタッチと再アタッチ

`ctrl+b q` でクライアントをデタッチします。ペインとエージェントは動き続けます。再度 `shepherd` を実行すると再アタッチします。セッションとそのペインを停止するには `shepherd server stop` を使います。

サーバーの完全停止後に Shepherd が再起動すると、保存されたセッションの形を復元します。デタッチ、サーバー再起動、画面履歴リプレイ、エージェントネイティブのセッション復元、ライブハンドオフでそれぞれ何が生き残るかは[セッション状態と復元](/ja/docs/session-state/)を参照してください。

## 名前付きセッション

独立した Shepherd サーバーが欲しいときは名前付きセッションを使います。

```bash
shepherd session list
shepherd session attach work
shepherd session attach side-project
shepherd session stop work
shepherd session delete side-project
```

名前付きセッションは独自のペイン、タブ、ワークスペース、ソケット、ランタイム状態を持ちます。グローバル設定ファイルは共有されます。

スクリプトでは `--json` を使ってください:

```bash
shepherd session list --json
shepherd session stop work --json
shepherd session delete side-project --json
```

## SSH 越しのリモートアタッチ

リモートモードは 2 つあり、[Shepherd での作業の進め方](/ja/docs/how-to-work/)で比較しています。tmux スタイルの方法では、サーバーに SSH してそこで `shepherd` を実行します。もうひとつは、ローカルマシンから SSH 越しにアタッチする方法です:

```bash
shepherd --remote workbox
shepherd --remote ssh://you@server:2222
```

このモードでは、ローカルの Shepherd はシンクライアントです。SSH 越しに接続し、リモートの Shepherd サーバーを起動またはアタッチして、UI をローカルターミナルにストリーミングします。クライアントがローカルで動くため、Shepherd は画像クリップボードの貼り付けのようなローカルデスクトップ機能をリモートセッションにブリッジできます。画像をリモートの一時ファイルにコピーし、そのパスを貼り付けます。

デフォルトでは、`shepherd --remote` はそのアタッチにローカルの Shepherd キーバインドを使います。リモートサーバーの設定が異なっていても、ローカルの操作感覚を維持できます。ローカルキーバインドはアタッチ時のスナップショットなので、ローカルのキーバインドを編集したらデタッチして再アタッチしてください。リモートサーバーの設定を使いたい場合は `--remote-keybindings server` を使います。ローカルのカスタムコマンドキーバインドは送信されません。それらのコマンドはリモートホスト上で実行されてしまうからです。

繰り返し接続する相手は SSH config を使ってください:

```text
Host workbox
  HostName server.example.com
  User you
  Port 2222
```

その後はこれでアタッチできます:

```bash
shepherd --remote workbox
```

リモートアタッチは x86_64 と aarch64 の Linux および macOS ホストをサポートします。Shepherd はリモートのプラットフォームと既知のインストール先を調べ、同じ Shepherd バージョンとプロトコルのピアを要求します。見つからない場合、対話的なアタッチではピア側の `shepherd-install` の実行を提案できます。非対話的な実行はホストを変更せず、同じ手順を示して失敗します。ピアにはあらかじめこのインストーラーが必要で、ビルドはそのホスト上でネイティブに行われます。

ネイティブ Windows の `shepherd --remote` は Windows ベータの範囲外です。Windows からはサーバーに SSH してそこで `shepherd` を実行してください。

デフォルトでは、`shepherd --remote` はあなたの SSH config を最初に include し、その後にフォールバックのキープアライブ設定を加えた一時的な SSH config を通してブリッジを実行します。既存のユーザーのキープアライブ設定が優先されます。Shepherd が生成するブリッジ設定を使わず素の `ssh` を使うには `[remote].manage_ssh_config = false` を設定してください。

デフォルトでは、実行中のリモートサーバーの置き換えや再起動が必要な場合、リモートアタッチは通常の再起動/停止フローを使います。対応する実行中リモートサーバーで実験的なライブハンドオフにオプトインするには `--handoff` を渡します:

```bash
shepherd --remote workbox --handoff
```

先にサーバーへ SSH してそこで `shepherd` を実行した場合、Shepherd は完全にサーバー上で動きます。このモードは便利でシンプルですが、通常のターミナルテキスト貼り付けを超えてローカルデスクトップのクリップボードにはアクセスできません。

Shepherd はローカルバイナリをピアへストリーミングせず、従来のアップストリームリリースをフォールバックとしてダウンロードすることもありません。ピアが未導入または非互換なら、そこで `shepherd-install` を実行するか、対話的な実行提案を承認してから、もう一度アタッチしてください。

## リモートの名前付きセッション

リモートホスト上の名前付きセッションにアタッチするには、`--remote` と一緒に `--session` を使います:

```bash
shepherd --remote workbox --session agents
```

## ダイレクトターミナルアタッチ

完全な Shepherd アタッチはワークスペース UI 全体を開きます。ダイレクトアタッチは、サーバーが所有するターミナルをひとつだけ、現在のターミナルに開きます。

ダイレクトターミナルアタッチは Windows ベータでは Unix 専用です。

エージェントターゲットでアタッチ:

```bash
shepherd agent attach reviewer
```

ターミナル ID でアタッチ:

```bash
shepherd terminal attach term_abc123
```

ダイレクトアタッチは、現在レンダリングされているターミナル状態をストリーミングし、その後ライブの ANSI フレームを流します。入力はそのターミナルに直接送られます。

`ctrl+b q` でデタッチします。リテラルの `ctrl+b` は `ctrl+b ctrl+b` で送ります。

ひとつのターミナルの入力とリサイズを所有できる書き込み可能なダイレクトアタッチクライアントはひとつだけです。既存の所有者を置き換えるには `--takeover` を使います:

```bash
shepherd terminal attach term_abc123 --takeover
```

## シングルプロセスの逃げ道

バックグラウンドのサーバー/クライアント分離なしで Shepherd を実行するには `--no-session` を使います:

```bash
shepherd --no-session
```

これは主にデバッグや互換性のための逃げ道です。デフォルトの永続セッションモードが通常の使い方です。
