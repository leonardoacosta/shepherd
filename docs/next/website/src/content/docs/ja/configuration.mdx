Shepherd は設定ファイルなしで動作します。キー、テーマ、サイドバーのレイアウト、通知、高度な挙動をカスタマイズしたい場合に追加してください。

設定やキーバインドを探していますか？すべてのキー、型、デフォルト値、許容値は[設定リファレンス](/docs/config-reference/)で検索できます。このページでは、セットアップ、一般的なレシピ、リファレンスの一行だけでは説明しきれない設定構造を中心に説明します。

## 設定ファイル

Shepherd は次の場所から設定を読み込みます:

```text
Linux and macOS: ~/.config/shepherd/config.toml
Windows:          %APPDATA%\shepherd\config.toml
```

システム上で解決された設定ファイルのパスは、`shepherd --help` で確認できます。

完全なデフォルト設定を表示します:

```bash
shepherd --default-config
```

完全な出発点が欲しい場合は、これを設定として保存してください:

```bash
shepherd --default-config > ~/.config/shepherd/config.toml
```

設定値が無効な場合、Shepherd は安全なデフォルト値にフォールバックし、起動時に警告を表示します。

`onboarding` が存在しないか true の場合、Shepherd は初回セットアップを表示します。オンボーディングから先へ進むと `onboarding = false` が書き込まれ、設定のインテグレーションタブが開きます。セットアップ後にこのフローをスキップしたい場合に設定してください。

```toml
onboarding = false
```

## 設定のリロード

`config.toml` を編集した後、実行中のサーバーをリロードします:

```bash
shepherd server reload-config
```

Shepherd のグローバルメニューを開いて `reload config` を選ぶこともできます。

リロードは、ペインを再起動せずにほとんどの UI 設定を適用します。起動時のみの設定には引き続き再起動が必要です。

## 設定画面

`prefix` + `s` で設定画面を開きます。このページの多くの値は、`config.toml` を直接編集しなくても設定画面から変更できます。

設定画面は、テーマ、サウンド、トースト、表示、動作、インテグレーション、実験的機能に分かれています。セクションと行は狭いターミナルでも到達可能です。セクション一覧は利用可能な幅に合わせて調整され、長い内容はスクロールし、選択中の行は常に表示されます。キーボードとマウスは同じ行を指すため、キーボードで到達できるものはクリックでも操作できます。

コントロールを変更すると、そのキーだけが `config.toml` に書き戻されます。周囲のコメントと無関係なキーは保持されます。これらのセクションのコントロールはすべて即座に適用され、再起動を必要とするものはありません。書き込みに失敗した場合や設定ファイルが壊れている場合は、最後に有効だった値が使われ続けます。

これらの厳選された行に含まれない設定については、実際の `config.toml` をエディタで直接開くアクションも用意されています（`$VISUAL`/`$EDITOR`、Unix では `vi`、Windows では Notepad にフォールバックします）。このアクションは `server.config.edit` リクエストを利用するため、TUI をローカルで実行していてもリモートサーバーに接続していても同じように動作します。保存して終了すると、正しい変更は即座にリロードされます。不正な変更はディスク上に保持され、診断情報が表示され、最後に有効だった設定がそのまま動作し続けるため、すぐに開き直して修正できます。

### 表示と動作

表示には視覚的な設定があります。ペインの境界線、ペインの間隔、Agent 境界ラベル、タブが 1 つだけのときのタブバーの非表示、Agent の並び順に加えて、後述のトップバーとドックのコントロールも含まれます。設定側の並び順コントロールとサイドバーのヘッダーのコントロールは同じ `ui.agent_panel_sort` の値を書き込むため、両者が食い違うことはありません。

動作には操作に関する設定があります。クローズ確認、タブとワークスペースの名前入力プロンプト、選択時コピー、マウスのスクロール速度です。

### インテグレーションの管理

インテグレーションには、既知のターゲットごとに現在の状態が `installed`、`update available`、`available`、`not found` のいずれかで表示されます。プラットフォームで未対応のターゲットや `PATH` に見つからないターゲットも、一覧から消えるのではなく理由付きで残り、操作は提供されません。

ターゲットを選んで Enter を押すと、状態に応じてインストール、更新、アンインストールの操作が表示されます。アンインストールは必ず確認を求め、対象とそのインストールパスを先に明示します。キャンセルすれば何も変更されません。対象となるすべてのターゲットへの一括インストールは、フッターの副次的な操作として引き続き利用できます。

インテグレーションの操作は同時に 1 つだけ実行され、実行中の追加操作は拒否されます。各ターゲットは結果の要約を個別に保持し、`d` を押すとスクロール可能な操作履歴全体が開くため、複数成功した後の失敗も狭いターミナルで確認できます。

## ターミナルのデフォルト

新しく作成される対話型ペインに Shepherd が使う実行ファイルを設定します:

```toml
[terminal]
default_shell = "nu"
```

未設定または空の場合、Shepherd は `$SHELL`、次に Unix では `/bin/sh`、Windows では PowerShell を使います。これは実行ファイル名またはパスであり、シェルのコマンドラインではありません。既存のペインは再作成されるまで現在のシェルを保ちます。カスタムコマンドキーバインドの文字列は、Unix ではペインコマンドに `/bin/sh -c`、デタッチコマンドに `/bin/sh -lc` を通して実行され、Windows では `cmd.exe /d /c` を通して実行されます。

新しく作成される対話型ペインのシェルの起動方法を設定します:

```toml
[terminal]
shell_mode = "auto"
```

`shell_mode = "auto"` は macOS でログインシェルを起動するため、`/usr/libexec/path_helper` のようなログイン時のみの PATH 設定や Homebrew のシェル初期化が新しいペインで実行されます。他のプラットフォームでは、既存の非ログインシェルの挙動を保ちます。ログインシェルでの起動を強制するには `"login"` を、無効にするには `"non_login"` を使ってください。コマンドペイン、デタッチされたカスタムコマンドキーバインド、明示的な argv 起動は、既存のコマンド実行経路を保ちます。

新しいペイン、タブ、ワークスペースの作業ディレクトリポリシーを設定します:

```toml
[terminal]
new_cwd = "follow"
```

`new_cwd = "follow"` はデフォルトの挙動を保ち、元のペインまたはワークスペースを継承します。元のワークスペースがない場合、Shepherd は `$HOME` で起動します。常に `$HOME` で起動するには `"home"` を、Shepherd のプロセスディレクトリを使うには `"current"` を、または `"~/Projects"` のような固定パスを使ってください。CLI またはソケット API から明示的に指定された `--cwd` の値は引き続き優先されます。

## Worktree

サイドバーから作成される Git worktree チェックアウトに Shepherd が使うルートディレクトリを設定します:

```toml
[worktrees]
directory = "~/.shepherd/worktrees"
```

Shepherd は `<directory>/<repo>/<branch-slug>` の下にチェックアウトを作成します。隣接ディレクトリ方式のチェックアウトには、`~/Projects/shepherd-worktrees` のようなディレクトリを設定してください。相対値は、アプリが設定を適用するときに絶対パスへ解決されます。

worktree アクションは Git ワークスペースの行から使えます。`New worktree` はチェックアウトを作成し、入力したブランチがすでに存在する場合は既存のローカルブランチをチェックアウトし、存在しない場合はブランチを作成します。その後、新しい Shepherd ワークスペースとして開き、元のワークスペースの下にグループ化します。`Open worktree...` はそのリポジトリにある既存の Git worktree チェックアウトを一覧表示します。すでに開いているチェックアウトを選ぶとそこへフォーカスし、閉じているチェックアウトを選ぶと同じグループで開きます。

グループ化された worktree も通常の Shepherd ワークスペースと同様に動作します。フォーカス、名前変更、クローズができ、それぞれ独自のタブとペインを持ちます。親の行は元のワークスペースです。親の行を閉じると Shepherd のグループ全体が閉じますが、チェックアウトのフォルダーやブランチは削除されません。

worktree チェックアウトの削除は明示的に行います。グループ化された子ワークスペースで `Delete worktree checkout...` を使うと `git worktree remove` が実行されます。Shepherd はまず Git に安全な削除を要求します。チェックアウトに変更済みまたは未追跡のファイルがあり Git が拒否した場合、Shepherd は強制削除を実行する前にもう一度確認します。ブランチは削除されません。

## リモートアタッチ

リモートアタッチは、デフォルトで一時的なキープアライブと接続再利用のフォールバックを使って SSH 接続を管理します。

```toml
[remote]
manage_ssh_config = true
```

有効な場合、`shepherd --remote` は最初に `~/.ssh/config` と `/etc/ssh/ssh_config` を取り込み、その後にフォールバックの `ServerAliveInterval` と `ServerAliveCountMax` の値を加えた、プライベートな一時 SSH 設定を書き込みます。ユーザー自身のキープアライブ設定が優先されます。Shepherd は、最初に認証した接続を再利用するため、アタッチごとにプライベートな OpenSSH コントロールソケットも使います。Shepherd が生成した設定やコントロールソケットを使わず、通常の `ssh` でリモートアタッチを実行するには `manage_ssh_config = false` を設定してください。

## キーバインド

プレフィックスの導入ガイドと検証済みのプレフィックスなし構成については、[キーボード](/docs/keyboard/)を参照してください。

Shepherd には tmux に似たプレフィックスモードがあります。デフォルトのプレフィックスは `ctrl+b` です。キーバインド文字列は明示的です。`prefix+n` は設定されたプレフィックスを押してから `n` を押すという意味で、`ctrl+alt+n` はターミナルモードの直接ショートカットです。

小さなキーバインドの上書きは次のようになります:

```toml
[keys]
prefix = "ctrl+b"
goto = "prefix+g"
new_tab = "prefix+c"
next_tab = "prefix+n"
previous_tab = "prefix+p"
focus_pane_left = "prefix+h"
navigate_workspace_down = "j"
navigate_pane_down = "ctrl+j"
split_horizontal = "prefix+minus"
```

デフォルトのキーマップはプレフィックス優先なので、Shepherd がシェル、エディタ、tmux、ターミナルアプリから入力を奪うことはありません。[設定リファレンス](/docs/config-reference/)で `keys.` を検索すると、すべてのアクションとデフォルトのバインドを確認できます。`prefix+?` で開くアプリ内ヘルプパネルには、現在有効なバインドが表示されます。

1 つのアクションに複数のショートカットが必要な場合、バインドを配列にすることもできます:

```toml
[keys]
next_tab = ["prefix+n", "ctrl+alt+]"]
```

任意のアクションはデフォルトでは未設定です。プレフィックスモードの挙動には `prefix+` でバインドし、意図的に直接ショートカットにする場合は明示的な修飾キーコードを使ってください。

キー文字列には、通常のキー、`ctrl+a`、`shift+n`、`alt+1`、`cmd+k` のような修飾キーの組み合わせ、`enter`、`tab`、`esc`、`left`、`right`、`up`、`down` のような特殊キーが使えます。`minus`、`comma`、`ampersand`、`plus`、`backtick` のような名前付き記号も使えます。`n` のような通常の印字可能キーの直接バインドは入力を妨げるため危険です。意図的に直接バインドするのでなければ `prefix+n` を使ってください。`navigate_workspace_*` と `navigate_pane_*` のフィールドはナビゲートモード専用で、`j` や `k` のような通常のキーを使えます。これらには `prefix+`、`esc`、`enter`、`tab`、`shift+tab`、`left`、`right`、修飾なしの `1` から `9` は使えません。左右の矢印キーは、左ペインと右ペインへのナビゲーションの恒久的なエイリアスです。これらのナビゲートモードショートカットは、`focus_pane_down = "prefix+j"` のような一般アクションのバインドから独立しています。両方に同じキーが使われている場合、ナビゲートモードが開いている間はナビゲートモードのショートカットが優先されます。Alt、Cmd/Super、修飾キー付き記号は、ターミナルと tmux の設定に依存します。

古いカスタムキーバインドを使っていて新しいデフォルトが欲しい場合は、`shepherd config reset-keys` を実行してください。Shepherd は `config.toml` をバックアップし、`[keys]` と `[[keys.command]]` を削除し、再起動または `shepherd server reload-config` の後に組み込みの v2 デフォルトを使います。

## インデックス付きジャンプ

インデックス付きキーバインドは、通常のキーバインドフィールドで `1..9` を使います:

```toml
[keys]
switch_tab = "prefix+1..9"
switch_workspace = "prefix+shift+1..9"
focus_agent = "prefix+alt+1..9"
```

レガシーな `[keys.indexed]` テーブルは互換性のために引き続きパースされますが、新しい設定では明示的なアクションフィールドを使ってください。

## カスタムコマンドキーバインド

カスタムコマンドも同じキーバインド構文を使います。

```toml
[[keys.command]]
key = "prefix+alt+g"
type = "popup"
command = "lazygit"
description = "run lazygit"
width = "80%"
height = "80%"
```

`type = "popup"` は、タブレイアウトを変更せずにセッションモーダルなポップアップを開きます。
ポップアップは、コマンドが終了するまで Escape を含むすべてのターミナル入力を受け取ります。
`width` と `height` は任意です。省略するとデフォルトの半分のサイズになり、数値ならターミナルセル数、`"80%"` のような文字列ならターミナル領域に対する割合を指定できます。
寸法にはポップアップの枠が含まれ、小さすぎる値は最小サイズに制限されます。
ポップアップコマンドは `SHEPHERD_PANE_ID` を受け取りません。背後のタイルペインには `SHEPHERD_ACTIVE_PANE_ID` を使ってください。

Unix と macOS では、分割やタブを追加せずに一時的なターミナルを開くこともできます:

```toml
[[keys.command]]
key = "prefix+t"
type = "popup"
command = "exec \"${SHELL:-sh}\""
description = "open scratch terminal"
width = "80%"
height = "80%"
```

Windows では、代わりに `command = "powershell.exe -NoLogo"` のようなシェルコマンドを使ってください。
シェルを終了するとポップアップが閉じ、タイル表示に戻ります。

`type = "pane"` は一時的なペインを開き、コマンドの終了時に閉じます。

`type = "shell"` はバックグラウンドでデタッチ実行します。

`type = "plugin_action"` はインストール済みプラグインのアクション id を呼び出します。アクション id がグローバルに一意でない場合は修飾 id を使ってください:

```toml
[[keys.command]]
key = "prefix+l"
type = "plugin_action"
command = "example.layout.apply"
description = "apply layout"
```

任意で `description` を指定できます。指定すると、キーバインドヘルプパネル（`prefix+?` で開く）に、デフォルトの `'custom command'` ラベルの代わりに表示されます。

カスタムコマンドは、利用可能な場合に `SHEPHERD_SOCKET_PATH`、`SHEPHERD_BIN_PATH`、`SHEPHERD_ACTIVE_WORKSPACE_ID`、`SHEPHERD_ACTIVE_TAB_ID`、`SHEPHERD_ACTIVE_PANE_ID`、`SHEPHERD_ACTIVE_PANE_CWD` を受け取ります。Shepherd が検出できる場合、シェルコマンドはフォーカス中のペインの作業ディレクトリから実行されます。

Windows では、カスタムコマンド文字列に `cmd.exe /d /c` が使われるため、環境変数には `%SHEPHERD_BIN_PATH%` 構文を使います。PowerShell 構文を実行するには、たとえば `powershell.exe -NoProfile -Command "..."` のように明示的に呼び出してください。

## テーマ

組み込みテーマを選びます:

```toml
[theme]
name = "catppuccin"
```

すべての組み込みテーマは、[設定リファレンス](/docs/config-reference/)で `theme.name` を検索してください。Shepherd の UI 色をホストターミナルの ANSI パレットに従わせたいときは `terminal` を使ってください。

ホストターミナルがライト/ダークの外観変更を報告したときに、Shepherd が自身の UI テーマを切り替えるようにするには、テーマの自動切り替えを有効にします:

```toml
[theme]
name = "catppuccin"
auto_switch = true
light_name = "catppuccin-latte"
dark_name = "catppuccin"
```

`auto_switch` のデフォルトは `false` なので、既存のテーマ設定は手動の挙動を保ちます。`light_name` または `dark_name` を省略すると、設定された `name` に対応する組み込みの姉妹テーマが存在する場合はそれを使います。たとえば `tokyo-night`/`tokyo-night-day` や `gruvbox`/`gruvbox-light` です。設定画面でテーマを手動選択すると `auto_switch` は無効になります。

個々の色を上書きできます:

```toml
[theme.custom]
panel_bg = "reset"
accent = "#a6e3a1"
green = "#a6e3a1"
blue = "#89b4fa"
red = "#f38ba8"
yellow = "#f9e2af"
```

色の値には、hex、名前付きの色、`rgb(r,g,b)`、または `reset`、`default`、`none`、`transparent` のようなリセットエイリアスが使えます。

## UI とサイドバー

サイドバーは Shepherd のメインダッシュボードです。サイズ、折りたたみモード、Agent の並び順、マウスの挙動、ペインの境界線、その他の表示設定については、[設定リファレンス](/docs/config-reference/)で `ui.` を検索してください。

### スペースと Agent のフラットな 1 つのリスト

サイドバーは 1 つのリストを描画します。各スペース行のすぐ下にそのスペースで動いている Agent の行が続き、その後に次のスペースが来ます。独立した Agent セクションも、その間のドラッグ可能な仕切りもありません。

Agent 行が切り替え先です。どのスペースからでも、選択するとその Agent のスペース・タブ・ペインがアクティブになります。タブ自体の行はありません。切り替える対象はタブの中の Agent です。

検出された Agent が 1 つもないスペースには、その下に `no agents` 行が明示的に表示されます。「ここでは何も動いていない」ことが空白から推測するのではなく見て分かります。折りたたまれた worktree の親は子行をまったく表示しないため、折りたたみとアイドル状態のスペースを区別できます。

worktree のグルーピング、折りたたみシェブロン、スペースのドラッグ並べ替え、表示位置によるショートカット番号、Agent の並び順コントロールは、いずれも 1 つのリストに対して従来どおり動作します。並び順コントロールはサイドバーのヘッダーにあり、各スペースの Agent をそのスペース行の下で並べ替えます。

以前のリリースでは、サイドバーはスペースのセクションと Agent のセクションにドラッグ可能な仕切りで分割され、その位置がセッションファイルに保存されていました。この仕切りは廃止されました。変更前に書かれたセッションファイルはそのまま復元でき、保存されていた仕切りの位置は無視されます。

### クロームパネルとドック

オプションのトップバー、右クロームパネル、プラグインドックは、デスクトップ専用のワークスペース表示です。モバイルの 1 カラムレイアウトでは領域を確保しません。

クロームパネルとドックは別のものです。クロームパネルは解決されたトークンを描画するだけで、ターミナルを持たず、フォーカスも受け取りません。ドックはライブのターミナルランタイムをホストし、そこへフォーカスを渡します。

サイドバーが左端の全高を占め、トップバーはその右からメインコンテンツの幅だけに続きます。トップバーを有効にしてもサイドバーが下へ押し下げられることはなくなりました。既存の `[ui.topbar] rows` の値はそのまま有効です。変わるのはトップバーが描画される領域だけで、トークンの変更はありません。

トップバーの 1 行以上のレイアウトは、Agent サイドバーと同じトークン語彙で設定します:

```toml
[ui.topbar]
enabled = true
rows = [
  ["state_icon", "workspace", "tab"],
  [{ token = "$summary", fg = "#89b4fa", bold = true }],
]
```

各内側の配列が 1 行です。値がないトークンと区切りは消え、完全に空の行は領域を使いません。`state_icon`、`state_text`、`tab`、`pane`、`agent`、ターミナルタイトルなどの組み込みトークンは、アクティブなメインタブでフォーカスされているペインを参照します。ドックのフォーカスはこのコンテキストを置き換えません。`workspace` はアクティブなワークスペースを使います。カスタム `$name` はワークスペースメタデータを優先し、なければメインペインのメタデータを使います。インラインの `fg`、`bold`、`dim` と区切りの規則も Agent 行と同じです。少なくとも 1 行のデスクトップ本体が残るよう、必要に応じて表示行数が制限されます。

右クロームパネルは同じトークン語彙を使い、反対側の端でターミナルの全高を占めます:

```toml
[ui.right_panel]
enabled = true
width = 24
rows = [
  ["state_icon", "agent"],
  [{ token = "$summary", dim = true }],
]
```

`width` は確保する列数です。メインコンテンツに少なくとも 1 列が残るよう両側のパネル幅が制限され、1 行も解決しないパネルは領域をまったく確保しません。行、トークン、省略、スタイルの挙動はトップバーと同一です。トークン語彙もリゾルバも 1 つだけです。

ワークスペース単位のプラグインドックは別に有効化し、配置を設定します:

```toml
[ui.dock]
enabled = true
side = "bottom" # または "right"
size = 10
```

`size` は下部ドックの高さ、または右ドックの幅をセル数で指定し、最小値は `3` です。ライブドックのサイズは、メインワークスペースに少なくとも 1 行または 1 列を残すよう制限されます。両方を収められない場合、メイン領域を壊さずにドックを非表示にします。ドックを有効にしてもプラグインコードは実行されません。

Settings の **Display** では、トップバーとドックの切り替え、ドックの向きとサイズの変更、ドック対応ペインの明示的な起動ができます。表示されるのは、有効で現在のプラットフォームに対応し、マニフェストが `placement = "dock"` のインストール済みプラグインペインだけです。候補がない場合は説明だけが表示されます。起動に失敗すると `plugin_dock_disabled` や `plugin_dock_occupied` などの操作可能なエラーを Settings に表示し、空の領域は確保しません。

ライブドックをクリックすると、アクティブなメインタブやペインを変えずに補助入力フォーカスを与えます。キー、貼り付け、選択、スクロールバック、アプリケーションのマウス報告はドックへ送られますが、Shepherd の prefix と直接ショートカットが常に優先されます。メイン領域をクリックまたはナビゲートすると入力先が戻ります。ドックを無効にするとプロセスを終了せずに非表示にして補助フォーカスを解除し、再度有効にすると同じライブペインを表示します。

ドックプロセスは非表示の backing tab を使います。通常のデスクトップ/モバイルのタブ一覧と TUI ナビゲーションには表示されませんが、中立なライブ tab/pane API ではその ID を参照できます。ディスクセッションのスナップショットには backing tab を保存しないため、Shepherd の再起動や復元でプラグインコードが自動実行されることはありません。Display から明示的に開き直してください。一方、Unix の互換性がある live handoff は実行中のランタイムを転送し、非公開のドック所有情報を復元します。互換性がない場合やメタデータが欠落・不正な場合は、ドック所有なしへ安全にフォールバックします。

カスタムトップバーメタデータは、ペインまたはワークスペースのメタデータ報告から提供される表示データです。Shepherd は値を解決して描画しますが、値を生成するスクリプトやプラグインのインストール、起動、監視、ライフサイクル推測は行いません。生成側は別に設定し、既存の clear、sequence、expiry 制御を使ってください。

### サイドバーの行レイアウト

展開されたデスクトップサイドバーでは、`rows` の各内側の配列が 1 行として描画されます。完全なデフォルトレイアウトは次のとおりです:

```toml
[ui.sidebar.agents]
row_gap = 0
rows = [
  ["state_icon", "workspace", "tab"],
  ["agent"],
]

[ui.sidebar.spaces]
row_gap = 0
rows = [
  ["state_icon", "workspace"],
  ["branch", "git_status"],
]
```

Agent の行では、次の組み込みトークンを使えます:

- `state_icon` — エージェントの意味的な状態を示す色付きアイコン。
- `state_text` — `idle`、`working`、`blocked`、`done`、`unknown`。報告された表示ラベルがある場合はそれも含みます。
- `workspace` — ワークスペース名。
- `tab` — 利用可能な場合はタブ名。
- `pane` — 利用可能な場合はペイン名。
- `agent` — 検出または報告されたエージェントの表示名。
- `terminal_title` — 安全性のための正規化後の最新の OSC 0/2 ターミナルタイトル。
- `terminal_title_stripped` — 認識された先頭のアクティビティまたはスピナーのグリフ 1 つと、それに続く空白を除去したターミナルタイトル。
- `spend` — スペースのチェックアウトにおける累計コスト。Shepherd 自身が解決します。外部プロセスからの報告を待つのではなく、Shepherd が独自のスケジュールでプロバイダーを実行します。プロバイダーが利用できない場合、またはプロバイダーが古い値として報告した場合は、未解決の `$name` と同様にトークンとその区切り文字が省略されます。
- `savings` — `llmtrim` ソースから、`spend` と同じ方法で解決される、プロンプトキャッシュによる累計節約額。`spend` とは独立して省略される — `llmtrim` バイナリが見つからない場合は両方省略されるが、それ以外の場合はどちらか一方だけが省略されることはない。
- `cache_read_tokens` — `llmtrim` からの累計キャッシュ読み取りトークン数。
- `instruction_total_bytes` — `llmtrim` とは別のプロバイダーである `context-floor` から解決される、命令バジェットの合計バイト数。以下の 4 つのトークンは、`context-floor` が利用できないとき、他のソースとは独立してまとめて省略される。
- `instruction_floor_warn` — `context-floor` がフロア警告状態をアクティブと報告したときのみレンダリングされる。それ以外は未解決の値と同様にトークンが省略される。
- `instruction_growth_pct` — 前回の観測からの命令バジェットの増加率。
- `instruction_dollars_per_1k_turns` — 命令バジェットの 1000 ターンあたりの推定ドルコスト。
- `model` — Shepherd 自身の永続セッションスナップショットストアから解決される、セッションのモデル名。これと以下の 3 つのトークンは、そのストアが解決できないとき、他のソースとは独立してまとめて省略される。
- `context_tokens` — セッションの現在のコンテキストウィンドウトークン数。
- `context_window_tokens` — セッションのコンテキストウィンドウサイズ。
- `session_count` — 永続セッションストアに現在存在するセッション数。
- `quota_remaining` — 新鮮で完全な使用状況データを持つ、ローカルで追跡されているすべてのアカウントの残りクォータの合計。Shepherd 自身の認証情報状態ディレクトリから読み取り専用で解決され、他のソースとは独立して省略される。
- `reset_at` — クールダウン中のローカルで追跡されているアカウントのうち、最も早いクールダウンリセット時刻。
- `context_occupancy_pct` — セッションのコンテキストウィンドウ占有率を整数パーセントで表したもの（例: `62%`）。上記の `context_tokens`/`context_window_tokens` に対する純粋な派生値であり、独自のソースを読み取らず、その 2 つと同じ条件で省略される。
- `context_handoff_warning` — セッションのコンテキスト占有率がハンドオフしきい値を超えたときのみレンダリングされる。それ以外は未解決の値と同様にトークンが省略される。
- `transcript_cost` — このペイン自身の Claude Code トランスクリプトの推定 USD コスト。Shepherd がトランスクリプトファイルを直接読み取って解決する。上記の他のセッションプロバイダートークンと異なり、これはワークスペース単位ではなくペイン単位である — 同じワークスペース内の 2 つのペインが異なる Claude Code セッションを実行し、異なるトランスクリプトを持つことがある。
- `transcript_input_tokens` — このペインのトランスクリプトからの累計入力トークン数。
- `transcript_output_tokens` — このペインのトランスクリプトからの累計出力トークン数。
- `transcript_cache_read_tokens` — このペインのトランスクリプトからの累計キャッシュ読み取りトークン数。
- `transcript_cache_write_tokens` — このペインのトランスクリプトからの累計キャッシュ書き込みトークン数。
- `transcript_last_context_tokens` — このペインのトランスクリプトにおける、最後のアシスタントメッセージの実際のコンテキストサイズ（累計合計ではない）。
- `transcript_message_count` — このペインのトランスクリプトに含まれるターン数。
- `transcript_duration` — このペインのトランスクリプトの最初から最後に観測されたタイムスタンプまでの経過時間。
- `$name` — `name` という名前のカスタムペインメタデータ。

Space の行では、次の組み込みトークンを使えます:

- `state_icon` — Space 内で集約されたエージェント状態を示す色付きアイコン。
- `state_text` — Space 内で集約されたエージェント状態のテキスト。
- `workspace` — ワークスペース名。
- `branch` — 利用可能な場合は Git ブランチ。
- `git_status` — 0 でない場合は Git の ahead と behind の件数。
- `proposals` — スペースのチェックアウトにある未アーカイブの変更提案と進行中の件数。`op: 2o 1ip` の形式です。
- `beads` — スペースのチェックアウトにある課題の open / ready / blocked 件数。`bd: 3o 1r 0b` の形式です。
- `$name` — `name` という名前のカスタムワークスペースメタデータ。

`proposals` と `beads` は Shepherd 自身のリフレッシュタイマーで取得します。Git ステータスより低頻度で、設定された行が実際にそのトークンを使っている場合にのみ実行されます。未設定のトークンはプロセスを起動しません。スペースが解決するチェックアウトを参照するため、リンクされたワークツリーは親ではなく自身の件数を表示し、同じチェックアウトの複数スペースは 1 回のリフレッシュを共有します。

これらは `openspec` と `bd` が `PATH` にあることを前提としますが、どちらも必須ではありません。プロバイダが存在しない、失敗する、タイムアウトする、想定外の出力を返す場合、そのトークンだけが値なしとなり、他の値がないトークンとまったく同じように省略されます。もう一方のトークンと Git 系トークンは影響を受けません。

トークンは設定された順序で描画されます。Shepherd は通常、隣接する値を ` · ` で区切り、`state_icon` の後には空白を 1 つ入れます。値がない場合、その値と区切りは表示されません。すべてのトークンに値がない行は表示されません。各レイアウトは最大 16 行、各行は最大 16 トークンです。

トークンエントリにはインラインのスタイルテーブルも使えます:

```toml
[ui.sidebar.agents]
rows = [
  ["state_icon", { token = "workspace", bold = false }, "tab"],
  [{ token = "$summary", fg = "#89b4fa", bold = true, dim = false }],
]
```

`fg` は厳密な `#RGB` または `#RRGGBB`、`bold` と `dim` は真偽値です。省略したフィールドはコンテキストのスタイルを保持し、明示的な `false` はその修飾を解除します。スタイルは 1 つの出現箇所だけに適用されます。`fg` を指定した `git_status` では、既定の緑/赤ではなく ahead と behind の両方が同じ色になります。区切りと行の背景は変更されません。

`row_gap` は、Agent パネルと Space パネルごとに、エントリ間の空白行数を指定します。デフォルトは `0` で、エントリを詰めて表示します。以前の間隔に戻すには `1` に設定します。`rows` で定義したコンテンツ行の間隔には影響しません。連続するインデントされた worktree の子は、1 つの Space グループとして詰めて表示されます。

既知のエージェントについて Agent の完全なレイアウトを上書きするには、`rows_by_agent` を使います:

```toml
[ui.sidebar.agents]
rows = [
  ["state_icon", "agent", "state_text"],
  ["workspace", "tab"],
]

[ui.sidebar.agents.rows_by_agent]
claude = [
  ["state_icon", "agent", "state_text"],
  ["terminal_title_stripped"],
  ["workspace", "tab"],
]
```

上書きは `rows` を置き換えるもので、拡張するものではありません。上書きのキーには、`claude`、`codex`、`pi` のような大文字と小文字を区別する正規エージェント ID を使います。`claude-code` のような検出エイリアスは使えません。カスタム報告されたエージェントを含め、上書きがないエージェントには `rows` が使われます。

カスタム `$name` トークンは動的な値であり、リテラルテキストではありません。トークンをレイアウトに追加してから、スクリプトまたはプラグインで値を報告します:

```toml
[ui.sidebar.agents]
rows = [
  ["state_icon", "agent", "$model"],
  ["$summary"],
  ["workspace", "tab"],
]
```

```bash
shepherd pane report-metadata <pane_id> \
  --source my-agent-hook \
  --token model=opus \
  --token summary="reviewing authentication"
```

カスタム Space トークンには、同じ方法で `shepherd workspace report-metadata` を使います。報告されていないカスタムトークンは表示されません。

メタデータの報告元が提供できるのは値だけで、スタイルはローカルのサイドバー設定で管理します。上限、クリア、シーケンス、有効期限については、[CLI リファレンス: report metadata](/docs/cli-reference/#panes)を参照してください。

サイドバーの行設定は、展開されたデスクトップサイドバーにだけ適用されます。折りたたみ表示とモバイル表示はコンパクトなレイアウトを保ちます。

## 通知

Shepherd は、バックグラウンドのエージェントが完了したり入力を必要としたりしたときに通知できます:

```toml
[ui.toast]
delivery = "shepherd"
delay_seconds = 1

[ui.toast.shepherd]
position = "bottom-right"
```

アプリ内トーストには `shepherd`、SSH 越しでも使いやすい外側のターミナル通知には `terminal`、ローカル OS の通知サービスには `system`、ポップアップを無効にするには `off` を選びます。Shepherd はアクティブなタブのポップアップを抑制します。位置、遅延の挙動、クリップボードのフィードバック設定については、[設定リファレンス](/docs/config-reference/)で `ui.toast` を検索してください。

## サウンド

サウンド通知はローカルの Shepherd クライアントで再生されます。カスタムサウンドは mp3 ファイルでなければなりません。相対パスは設定ファイルのディレクトリから解決されます。

```toml
[ui.sound]
path = "sounds/notification.mp3"
done_path = "sounds/done.mp3"
request_path = "sounds/request.mp3"
```

`path` はすべてのサウンド通知に 1 つの音を設定します。`done_path` と `request_path` は、完了音と入力要求音だけを上書きします。

エージェント別のサウンド上書きには `default`、`on`、`off` を指定できます。キーには `claude`、`codex`、`devin`、`droid` のような検出されたエージェントラベルを使います。Droid はデフォルトでミュートされています。

```toml
[ui.sound.agents]
droid = "off"
claude = "on"
```

## 高度な設定

スクロールバックの上限、ネストされた起動、その他の高度な設定や実験的設定については、[設定リファレンス](/docs/config-reference/)を検索してください。ペイン画面履歴を有効にする前に、[セッション状態と復元](/docs/session-state/)を参照してください。このガイドでは、ペインの内容を保存する場合のセキュリティ上のトレードオフを説明しています。

## Kitty graphics

アタッチされたローカルクライアントでの Kitty graphics の描画は実験的機能で、デフォルトでは無効です:

```toml
[experimental]
kitty_graphics = true
```

ターミナルの画像表示をテストする場合にのみ有効にしてください。

## Agent セッション復元

Shepherd はデフォルトで、サーバーの再起動後に対応する Agent の会話を再開します:

```toml
[session]
resume_agents_on_restore = true
```

公式インテグレーションからの有効なネイティブセッション参照を持つペインだけが再開できます。その他のペインは通常のシェルとして復元されます。対応する Agent と永続化の挙動については、[セッション状態と復元](/docs/session-state/)を参照してください。

## IME カーソルトラッキング

macOS では、ハードウェアカーソルを隠す AI Agent TUI によって、ネイティブ入力メソッドの変換候補ウィンドウがフォーカス中のペインを追跡できなくなることがあります。これらのペインでカーソルアンカーを表示するには、次のように設定します:

```toml
[experimental]
reveal_hidden_cursor_for_cjk_ime = true
cjk_ime_agents = ["claude", "pi", "codex"]
```

`cjk_ime_agents` で対象を限定すると、関係のないアプリケーションに余分なハードウェアカーソルが表示されるのを避けられます。使用できる Agent 名とカーソル形状については、[設定リファレンス](/docs/config-reference/)でこれらのキーを検索してください。

## プレフィックス入力ソースの切り替え

macOS と Windows では、プレフィックスコマンドとプレフィックスから起動したモードがアクティブな間、Shepherd が ASCII 対応の入力ソースへ一時的に切り替えるようにできます:

```toml
[experimental]
switch_ascii_input_source_in_prefix = true
```

macOS ではその時点の ASCII 対応キーボードレイアウトへ切り替えます。Windows では IME を英語（ASCII）入力へ切り替えます。ターミナル入力に戻るかテキストフィールドに入ると、Shepherd は以前の入力ソースを復元します。この設定は他のプラットフォームには影響しません。

:::caution[Windows では韓国語 IME のみ対応]
Windows でのサポートは現時点で韓国語 IME に限定されています。それ以外の言語の IME を使用している場合、この設定は入力ソースを変更しません。
:::

## 環境変数

| `SHEPHERD_CONFIG_PATH` | 設定ファイルのパスを上書きする。 |
| `SHEPHERD_SESSION` | CLI コマンドで名前付きセッションを選択する。 |

## ログ

ログは、起動時の警告、インテグレーションの状態、ソケット API の挙動を診断するときに役立ちます。

主なログファイル:

```text
~/.config/shepherd/shepherd.log
~/.config/shepherd/shepherd-client.log
~/.config/shepherd/shepherd-server.log
```

ログは自動的にローテーションされます。問題を報告するときは、現在のログとローテーションされた関連ファイルを含めてください。
