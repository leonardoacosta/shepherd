Shepherd 无需配置文件即可使用。当你想自定义按键、主题、侧边栏布局、通知或高级行为时，再添加配置文件。

在查找某项设置或按键绑定？请在[配置参考](/docs/config-reference/)中搜索，其中列出了每个键、类型、默认值和允许值。本页重点介绍设置方法、常用配置方案，以及需要比参考表格更详细说明的配置结构。

## 配置文件

Shepherd 从以下位置读取配置：

```text
Linux and macOS: ~/.config/shepherd/config.toml
Windows:          %APPDATA%\shepherd\config.toml
```

运行 `shepherd --help` 可查看系统解析后的配置路径。

打印完整的默认配置：

```bash
shepherd --default-config
```

如果想从完整配置开始，可以将其保存为你的配置文件：

```bash
shepherd --default-config > ~/.config/shepherd/config.toml
```

如果配置值无效，Shepherd 会回退到安全的默认值，并显示启动警告。

当 `onboarding` 缺失或为 true 时，Shepherd 会显示首次运行设置。继续完成引导会写入 `onboarding = false`，并打开设置中的集成标签页。完成设置后，如果想跳过此流程，请设置该值。

```toml
onboarding = false
```

## 重载配置

编辑 `config.toml` 后，重载正在运行的服务器：

```bash
shepherd server reload-config
```

你也可以打开 Shepherd 的全局菜单并选择 `reload config`。

重载会在不重启窗格的情况下应用大多数 UI 设置。仅启动时生效的设置仍需重启。

## 设置界面

使用 `prefix` + `s` 打开设置界面。本页中的许多值都可以在设置界面中修改，无需手动编辑 `config.toml`。

设置界面分为主题、声音、提示、显示、行为、集成和实验性功能等部分。在较小的终端上，各部分和各行仍然可达：部分列表会根据可用宽度自适应，较长的内容可以滚动，所选行始终保持可见。键盘和鼠标指向同一批行，因此键盘可达的内容也可以点击操作。

修改某个控件只会将该键写回 `config.toml`。周围的注释和无关的键都会保留。这些部分中的所有控件都会立即生效，无需重启。如果写入失败或配置文件格式有误，将继续使用最后一个有效值。

对于这些精选行未覆盖的设置，设置界面还提供了一个直接在编辑器中打开真实 `config.toml` 的操作（使用 `$VISUAL`/`$EDITOR`，在 Unix 上回退到 `vi`，在 Windows 上回退到 Notepad）。该操作复用 `server.config.edit` 请求，因此无论 TUI 在本地运行还是连接到远程服务器，行为都一致。保存并退出后：有效的修改会立即重新加载；无效的修改会保留在磁盘上并给出诊断信息，同时最后一个有效配置继续运行，你可以立即重新打开并修正。

### 显示与行为

显示部分包含视觉相关的设置：窗格边框、窗格间距、Agent 边框标签、仅有一个标签页时隐藏标签栏，以及 Agent 排序方式，另外还有下文介绍的顶栏和停靠区控件。设置中的排序控件与侧边栏表头的控件写入同一个 `ui.agent_panel_sort` 值，因此两者不会出现分歧。

行为部分包含交互相关的设置：关闭确认、标签页和工作区命名提示、选中即复制，以及鼠标滚动速度。

### 管理集成

集成部分会列出每个已知目标的当前状态：`installed`、`update available`、`available` 或 `not found`。在当前平台不受支持或未在 `PATH` 中找到的目标不会从列表中消失，而是保留并附上原因，且不提供任何操作。

选中某个目标并按 Enter 可打开其操作：根据状态提供安装、更新或卸载。卸载总会要求确认，并先明确给出目标及其安装路径；取消则不会做任何更改。批量安装所有符合条件的目标仍作为页脚的次要操作保留。

同一时间只会执行一个集成操作，运行期间的再次尝试会被拒绝。每个目标都会单独保留自己的结果摘要，按 `d` 可打开完整的可滚动操作历史，因此在多次成功之后出现的失败仍然可以在小终端上看到并访问。

## 终端默认值

设置 Shepherd 创建新交互式窗格时使用的可执行文件：

```toml
[terminal]
default_shell = "nu"
```

未设置或值为空时，Shepherd 会依次使用 `$SHELL`、Unix 上的 `/bin/sh` 或 Windows 上的 PowerShell。该值是可执行文件名或路径，而不是 shell 命令行。现有窗格会保留当前 shell，直到重新创建。自定义命令按键绑定中的字符串在 Unix 上通过 `/bin/sh -c` 执行窗格命令，通过 `/bin/sh -lc` 执行分离式命令；在 Windows 上则通过 `cmd.exe /d /c` 执行。

设置 Shepherd 如何启动新建交互式窗格的 shell：

```toml
[terminal]
shell_mode = "auto"
```

`shell_mode = "auto"` 会在 macOS 上启动登录 shell，让 `/usr/libexec/path_helper` 等仅登录时生效的 PATH 设置和 Homebrew shell 初始化在新窗格中运行。在其他平台上，它会保持现有的非登录 shell 行为。使用 `"login"` 强制以登录 shell 启动，或使用 `"non_login"` 禁用登录 shell。命令窗格、分离式自定义命令按键绑定和显式 argv 启动仍使用现有的命令执行路径。

设置新窗格、标签页和工作区的工作目录策略：

```toml
[terminal]
new_cwd = "follow"
```

`new_cwd = "follow"` 保持默认行为，并继承来源窗格或工作区。没有来源工作区时，Shepherd 从 `$HOME` 启动。使用 `"home"` 可始终从 `$HOME` 启动，使用 `"current"` 可采用 Shepherd 的进程目录，也可以指定 `"~/Projects"` 这样的固定路径。CLI 或 socket API 显式提供的 `--cwd` 值仍然优先。

## Worktree

设置 Shepherd 从侧边栏创建 Git worktree 检出时使用的根目录：

```toml
[worktrees]
directory = "~/.shepherd/worktrees"
```

Shepherd 会在 `<directory>/<repo>/<branch-slug>` 下创建检出。若要使用同级目录风格的检出，请将其设置为 `~/Projects/shepherd-worktrees` 这样的目录。应用配置时，相对路径会解析为绝对路径。

Git 工作区行提供 worktree 操作。`New worktree` 会创建检出：如果输入的分支已存在，则检出该本地分支，否则创建该分支；随后将其作为新的 Shepherd 工作区打开，并归组到来源工作区下。`Open worktree...` 会列出该仓库现有的 Git worktree 检出；选择已打开的检出会聚焦它，选择尚未打开的检出会在同一组中打开它。

归组的 worktree 仍像普通 Shepherd 工作区一样工作：可以聚焦、重命名和关闭，也可以拥有自己的标签页和窗格。父行是原始工作区。关闭父行会关闭整个 Shepherd 组，但不会删除检出目录或分支。

删除 worktree 检出需要显式操作。在归组的子工作区上使用 `Delete worktree checkout...` 来运行 `git worktree remove`。Shepherd 会先请求 Git 安全删除。如果 Git 因检出中存在已修改或未跟踪的文件而拒绝，Shepherd 会在强制删除前再次确认。分支不会被删除。

## 远程连接

远程连接默认使用临时保活设置和连接复用兜底来管理 SSH 连接。

```toml
[remote]
manage_ssh_config = true
```

启用后，`shepherd --remote` 会写入一份私有的临时 SSH 配置：先包含你的 `~/.ssh/config` 和 `/etc/ssh/ssh_config`，再添加兜底的 `ServerAliveInterval` 和 `ServerAliveCountMax` 值。你自己的保活设置优先。Shepherd 还会为每次远程连接使用私有的 OpenSSH control socket，以复用首次通过身份验证的连接。设置 `manage_ssh_config = false` 可通过普通 `ssh` 进行远程连接，不使用 Shepherd 生成的配置或 control socket。

## 按键绑定

有关前缀键的引导式介绍和经过验证的免前缀配置，请参阅[键盘](/docs/keyboard/)。

Shepherd 提供类似 tmux 的前缀模式。默认前缀是 `ctrl+b`。按键绑定字符串是显式的：`prefix+n` 表示先按配置的前缀，再按 `n`；`ctrl+alt+n` 则是终端模式下的直接快捷键。

一个简短的按键绑定覆盖如下：

```toml
[keys]
prefix = "ctrl+b"
goto = "prefix+g"
new_tab = "prefix+c"
next_tab = "prefix+n"
previous_tab = "prefix+p"
focus_pane_left = "prefix+h"
navigate_workspace_down = "j"
navigate_pane_down = "ctrl+j"
split_horizontal = "prefix+minus"
```

默认键位以前缀为主，因此 Shepherd 不会抢占 shell、编辑器、tmux 或终端应用的输入。在[配置参考](/docs/config-reference/)中搜索 `keys.` 可查看每个动作及其默认绑定。应用内帮助面板可通过 `prefix+?` 打开，其中会显示当前生效的绑定。

当一个动作需要多个快捷键时，绑定也可以是数组：

```toml
[keys]
next_tab = ["prefix+n", "ctrl+alt+]"]
```

可选动作默认不设置。使用 `prefix+` 可获得前缀模式行为；当你确实需要直接快捷键时，请使用显式的修饰组合键。

按键字符串支持普通按键、`ctrl+a`、`shift+n`、`alt+1`、`cmd+k` 等修饰组合键，以及 `enter`、`tab`、`esc`、`left`、`right`、`up`、`down` 等特殊键。也支持 `minus`、`comma`、`ampersand`、`plus`、`backtick` 等命名标点。直接绑定 `n` 这样的普通可打印键并不安全，因为它会拦截输入；除非你有意设置直接绑定，否则请使用 `prefix+n`。`navigate_workspace_*` 和 `navigate_pane_*` 字段仅在导航模式中生效，可以使用 `j` 或 `k` 等普通按键；它们不得使用 `prefix+`、`esc`、`enter`、`tab`、`shift+tab`、`left`、`right`，也不得使用无修饰键的 `1` 到 `9`。左右方向键是向左和向右导航窗格的永久别名。这些导航模式快捷键独立于 `focus_pane_down = "prefix+j"` 等通用动作绑定；两者使用同一按键时，打开导航模式后，导航模式快捷键优先。Alt、Cmd/Super 以及带修饰键的标点取决于你的终端和 tmux 设置。

如果你已有旧的自定义按键绑定，并想使用新的默认值，请运行 `shepherd config reset-keys`。Shepherd 会备份 `config.toml`，移除 `[keys]` 和 `[[keys.command]]`，并在重启或执行 `shepherd server reload-config` 后使用内置的 v2 默认值。

## 索引跳转

索引式按键绑定在普通按键绑定字段中使用 `1..9`：

```toml
[keys]
switch_tab = "prefix+1..9"
switch_workspace = "prefix+shift+1..9"
focus_agent = "prefix+alt+1..9"
```

旧版 `[keys.indexed]` 表仍会出于兼容性而解析，但新配置应优先使用显式的动作字段。

## 自定义命令按键绑定

自定义命令使用相同的按键绑定语法。

```toml
[[keys.command]]
key = "prefix+alt+g"
type = "popup"
command = "lazygit"
description = "run lazygit"
width = "80%"
height = "80%"
```

`type = "popup"` 会打开一个会话级模态弹窗,而不改变标签页布局。
弹窗会接收包括 Escape 在内的所有终端输入,直到命令退出。
`width` 和 `height` 是可选的;省略时默认为终端大小的一半,数字表示终端单元格数,`"80%"` 这样的字符串表示终端区域的百分比。
尺寸包含弹窗边框,过小的值会限制为弹窗最小尺寸。
弹窗命令不会收到 `SHEPHERD_PANE_ID`;可使用 `SHEPHERD_ACTIVE_PANE_ID` 引用底层平铺窗格。

在 Unix 和 macOS 上,还可以打开一个临时终端,而无需添加分割或标签页:

```toml
[[keys.command]]
key = "prefix+t"
type = "popup"
command = "exec \"${SHELL:-sh}\""
description = "open scratch terminal"
width = "80%"
height = "80%"
```

在 Windows 上,请改用 `command = "powershell.exe -NoLogo"` 之类的 shell 命令。
退出 shell 即可关闭弹窗并恢复平铺终端视图。

`type = "pane"` 会打开一个临时窗格，并在命令退出时关闭它。

`type = "shell"` 会在后台分离运行。

`type = "plugin_action"` 会调用已安装插件的动作 id。当动作 id 并非全局唯一时，请使用限定 id：

```toml
[[keys.command]]
key = "prefix+l"
type = "plugin_action"
command = "example.layout.apply"
description = "apply layout"
```

可以提供可选的 `description`。指定后，该描述会在按键绑定帮助面板（通过 `prefix+?` 打开）中显示，替代默认的 `'custom command'` 标签。

在相应值可用时，自定义命令会收到 `SHEPHERD_SOCKET_PATH`、`SHEPHERD_BIN_PATH`、`SHEPHERD_ACTIVE_WORKSPACE_ID`、`SHEPHERD_ACTIVE_TAB_ID`、`SHEPHERD_ACTIVE_PANE_ID` 和 `SHEPHERD_ACTIVE_PANE_CWD`。当 Shepherd 能检测到聚焦窗格的工作目录时，shell 命令会从该目录运行。

在 Windows 上，自定义命令字符串使用 `cmd.exe /d /c`，因此环境变量应采用 `%SHEPHERD_BIN_PATH%` 语法。若要运行 PowerShell 语法，请显式调用它，例如 `powershell.exe -NoProfile -Command "..."`。

## 主题

选择内置主题：

```toml
[theme]
name = "catppuccin"
```

在[配置参考](/docs/config-reference/)中搜索 `theme.name` 可查看所有内置主题。如果想让 Shepherd UI 颜色跟随宿主终端的 ANSI 调色板，请使用 `terminal`。

要让 Shepherd 在宿主终端报告明暗外观变化时自动切换自身的 UI 主题，请启用主题自动切换：

```toml
[theme]
name = "catppuccin"
auto_switch = true
light_name = "catppuccin-latte"
dark_name = "catppuccin"
```

`auto_switch` 默认为 `false`，因此现有主题配置会保持手动行为。如果省略 `light_name` 或 `dark_name`，且配置的 `name` 存在对应的内置姊妹主题，Shepherd 会使用该主题，例如 `tokyo-night`/`tokyo-night-day` 或 `gruvbox`/`gruvbox-light`。在设置中手动选择主题会禁用 `auto_switch`。

你可以覆盖单个颜色：

```toml
[theme.custom]
panel_bg = "reset"
accent = "#a6e3a1"
green = "#a6e3a1"
blue = "#89b4fa"
red = "#f38ba8"
yellow = "#f9e2af"
```

颜色值支持十六进制、命名颜色、`rgb(r,g,b)`，以及 `reset`、`default`、`none`、`transparent` 等重置别名。

## UI 与侧边栏

侧边栏是 Shepherd 的主仪表盘。在[配置参考](/docs/config-reference/)中搜索 `ui.`，可查看尺寸、折叠模式、Agent 排序、鼠标行为、窗格边框和其他显示设置。

### 空间与 Agent 的单一扁平列表

侧边栏只渲染一个列表。每个空间行的正下方是该空间中正在运行的 Agent 行，然后是下一个空间。不再有独立的 Agent 区域，也没有两者之间可拖动的分隔条。

Agent 行就是切换目标。无论当前处于哪个空间，选中它都会激活该 Agent 所属的空间、标签页和窗格。标签页没有自己的行——你切换的是标签页中的 Agent。

未检测到任何 Agent 的空间会在其下方显示一行明确的 `no agents`，让"这里什么都没在跑"直接可见，而不是从空白中推断。折叠的 worktree 父项完全不显示子行，这正是折叠与空闲空间的区别。

worktree 分组、折叠箭头、空间拖动排序、按可见位置编号的快捷键，以及 Agent 排序控件，都在这一个列表上照常工作。排序控件位于侧边栏表头，并在每个空间行下方为该空间的 Agent 排序。

早期版本把侧边栏分成空间区域和 Agent 区域，中间有可拖动的分隔条，并把分隔条位置保存在会话文件中。该分隔条已移除。此前写入的会话文件仍可正常恢复，其中保存的分隔条位置会被忽略。

### 界面面板和停靠区

可选的顶栏、右侧界面面板和插件停靠区是仅用于桌面布局的工作区界面；在移动端单列布局中不会占用空间。

界面面板和停靠区是两种不同的东西。界面面板只渲染已解析的 token，不承载终端，也不接受焦点。停靠区承载活动的终端运行时，并将焦点路由到它。

侧边栏占据左侧边缘的完整高度，顶栏从它的右边开始，只横跨主内容宽度；启用顶栏不再把侧边栏向下挤压。现有的 `[ui.topbar] rows` 配置仍然有效——改变的只是顶栏的渲染区域，没有任何 token 发生变化。

顶栏的一行或多行布局使用与 Agent 侧边栏相同的 token 词汇：

```toml
[ui.topbar]
enabled = true
rows = [
  ["state_icon", "workspace", "tab"],
  [{ token = "$summary", fg = "#89b4fa", bold = true }],
]
```

每个内层数组对应一行。没有值的 token 及其分隔符会消失，完全为空的行不会占用空间。`state_icon`、`state_text`、`tab`、`pane`、`agent` 和终端标题等内置 token 来自当前主标签页中获得焦点的窗格；停靠区焦点不会替换这一上下文。`workspace` 使用当前工作区。自定义 `$name` 优先使用工作区元数据，缺失时再使用主窗格元数据。内联 `fg`、`bold`、`dim` 样式和分隔规则也与 Agent 行一致。必要时 Shepherd 会裁剪已解析的行，确保桌面主体至少保留一行。

右侧界面面板使用相同的 token 词汇，并在另一侧边缘占据终端的完整高度：

```toml
[ui.right_panel]
enabled = true
width = 24
rows = [
  ["state_icon", "agent"],
  [{ token = "$summary", dim = true }],
]
```

`width` 是预留的列数。Shepherd 会限制两侧面板的宽度，确保主内容至少保留一列；解析不出任何行的面板不会占用任何空间。行、token、省略和样式的行为与顶栏完全一致——只有一套 token 词汇和一个解析器。

工作区级插件停靠区需单独启用并设置位置：

```toml
[ui.dock]
enabled = true
side = "bottom" # 或 "right"
size = 10
```

`size` 表示底部停靠区的高度或右侧停靠区的宽度，单位为终端单元格，最小值为 `3`。活动停靠区的大小会受限，以便主工作区至少保留一行或一列；终端无法同时容纳两者时，Shepherd 会隐藏停靠区几何，而不会使主区域不可用。启用停靠区只允许显示，并不会运行插件代码。

在 Settings 中选择 **Display**，可切换顶栏和停靠区、更改停靠区方向或大小，并显式打开支持停靠区的窗格。Shepherd 只列出已启用、支持当前平台且清单使用 `placement = "dock"` 的已安装插件窗格。没有候选项时只显示说明。启动失败时，Settings 会保留并显示 `plugin_dock_disabled`、`plugin_dock_occupied` 等可操作错误；失败的启动不会留下空白占位区域。

点击活动停靠区会授予辅助输入焦点，但不会改变当前主标签页或窗格。按键、粘贴、选择、回滚和应用程序鼠标报告随后发往停靠区，同时 Shepherd 的 prefix 和直接快捷键仍然优先。点击或导航主工作区会把输入焦点移回主区域。禁用停靠区会隐藏它并清除辅助焦点，但不会终止进程；重新启用后会显示同一个活动窗格。

停靠区进程使用隐藏的 backing tab。普通桌面/移动端标签页列表和 TUI 标签页导航会忽略它，但中立的实时 tab/pane API 仍可访问其标识。磁盘会话快照不包含 backing tab，因此重启或恢复 Shepherd 不会自动再次运行停靠区插件代码；请从 Display 显式重新打开。兼容的 Unix live handoff 则不同：它会转移已经运行的 runtime，并恢复私有的停靠区所有权。handoff 不兼容、元数据缺失或无效时，会安全回退为无停靠区所有权。

自定义顶栏元数据是通过窗格或工作区元数据报告提供的显示数据。Shepherd 会解析并渲染这些值，但不会安装、启动、监管或推断产生这些值的脚本或插件的生命周期。请单独配置生产方，并使用现有的 clear、sequence 和 expiry 控制。

### 侧边栏行布局

展开的桌面侧边栏会将 `rows` 中的每个内层数组渲染为一行。以下是完整的默认布局：

```toml
[ui.sidebar.agents]
row_gap = 0
rows = [
  ["state_icon", "workspace", "tab"],
  ["agent"],
]

[ui.sidebar.spaces]
row_gap = 0
rows = [
  ["state_icon", "workspace"],
  ["branch", "git_status"],
]
```

Agent 行支持以下内置 token：

- `state_icon` — 智能体语义状态的彩色图标。
- `state_text` — `idle`、`working`、`blocked`、`done` 或 `unknown`；如果报告中包含显示标签，也会一并显示。
- `workspace` — 工作区名称。
- `tab` — 标签页名称（如有）。
- `pane` — 窗格名称（如有）。
- `agent` — 检测到或报告的智能体显示名称。
- `terminal_title` — 经过安全规范化的最新 OSC 0/2 终端标题。
- `terminal_title_stripped` — 从终端标题开头移除一个可识别的活动或旋转指示符字形及其后空白后的结果。
- `$name` — 名为 `name` 的自定义窗格元数据。

Space 行支持以下内置 token：

- `state_icon` — Space 汇总后智能体状态的彩色图标。
- `state_text` — Space 汇总后智能体状态的文本。
- `workspace` — 工作区名称。
- `branch` — Git 分支（如有）。
- `git_status` — 非零时显示 Git ahead 和 behind 数量。
- `proposals` — 该空间检出目录中未归档和进行中的变更提案数量，格式为 `op: 2o 1ip`。
- `beads` — 该空间检出目录中 open、ready 和 blocked 的跟踪问题数量，格式为 `bd: 3o 1r 0b`。
- `$name` — 名为 `name` 的自定义工作区元数据。

`proposals` 和 `beads` 由 Shepherd 使用自己的刷新计时器计算，频率低于 Git 状态，并且只在已配置的行确实用到这些 token 时才会执行——未配置的 token 不会启动任何进程。它们读取该空间解析到的检出目录，因此关联工作树报告自己的数量而不是父仓库的，并且指向同一检出目录的多个空间共享一次刷新。

它们依赖 `PATH` 中存在 `openspec` 和 `bd`，但两者都不是必需的。当某个提供方缺失、失败、超时或返回非预期内容时，只有它自己的 token 没有值，并且会像任何其他缺失 token 一样被省略。另一个 token 和所有 Git token 都不受影响。

token 会按配置顺序渲染。Shepherd 通常使用 ` · ` 分隔相邻值，并在 `state_icon` 后使用一个空格。缺失值及其分隔符会消失；当一行中的所有 token 都没有值时，该行会消失。每个布局最多可包含 16 行，每行最多可包含 16 个 token。

也可以用内联样式表定义 token：

```toml
[ui.sidebar.agents]
rows = [
  ["state_icon", { token = "workspace", bold = false }, "tab"],
  [{ token = "$summary", fg = "#89b4fa", bold = true, dim = false }],
]
```

`fg` 只接受严格的 `#RGB` 或 `#RRGGBB`，`bold` 和 `dim` 接受布尔值。省略字段会保留上下文样式；显式 `false` 会移除对应修饰。样式只作用于当前出现位置。为 `git_status` 设置 `fg` 后，ahead 和 behind 会使用同一种颜色，而不是默认的绿色和红色。token 样式不会改变分隔符或行背景。

`row_gap` 分别控制 Agent 和 Space 面板中条目之间的空白终端行数。默认值为 `0`，会紧密排列条目；设为 `1` 可恢复之前的间距。它不会在 `rows` 声明的内容行之间添加间距。连续缩进的 worktree 子项仍会作为一个 Space 组紧密排列。

在 `rows_by_agent` 下为已知智能体覆盖完整的 Agent 布局：

```toml
[ui.sidebar.agents]
rows = [
  ["state_icon", "agent", "state_text"],
  ["workspace", "tab"],
]

[ui.sidebar.agents.rows_by_agent]
claude = [
  ["state_icon", "agent", "state_text"],
  ["terminal_title_stripped"],
  ["workspace", "tab"],
]
```

覆盖项会替换 `rows`，而不是扩展它。覆盖项的键是区分大小写的规范智能体 ID，例如 `claude`、`codex` 和 `pi`。不接受 `claude-code` 等检测别名。没有覆盖项的智能体（包括自定义报告的智能体）会使用 `rows`。

自定义 `$name` token 是动态值，而不是字面文本。先将 token 添加到布局，再通过脚本或插件报告其值：

```toml
[ui.sidebar.agents]
rows = [
  ["state_icon", "agent", "$model"],
  ["$summary"],
  ["workspace", "tab"],
]
```

```bash
shepherd pane report-metadata <pane_id> \
  --source my-agent-hook \
  --token model=opus \
  --token summary="reviewing authentication"
```

自定义 Space token 可用同样的方式通过 `shepherd workspace report-metadata` 报告。未报告的自定义 token 会直接消失。

元数据上报方只提供值；样式由本地侧边栏配置控制。有关限制、清除、顺序和过期值的信息，请参阅 [CLI 参考：报告元数据](/docs/cli-reference/#panes)。

侧边栏行设置仅影响展开的桌面侧边栏。折叠视图和移动视图仍使用紧凑布局。

## 通知

当后台智能体完成任务或需要输入时，Shepherd 可以通知你：

```toml
[ui.toast]
delivery = "shepherd"
delay_seconds = 1

[ui.toast.shepherd]
position = "bottom-right"
```

选择 `shepherd` 可使用应用内 toast，选择 `terminal` 可使用适合 SSH 场景的外层终端通知，选择 `system` 可使用本地操作系统通知服务，选择 `off` 可禁用弹出通知。Shepherd 会抑制活动标签页的弹出通知。在[配置参考](/docs/config-reference/)中搜索 `ui.toast`，可查看位置、延迟行为和剪贴板反馈设置。

## 声音

声音通知通过本地 Shepherd 客户端播放。自定义声音必须是 mp3 文件；相对路径从配置文件所在目录解析。

```toml
[ui.sound]
path = "sounds/notification.mp3"
done_path = "sounds/done.mp3"
request_path = "sounds/request.mp3"
```

`path` 为所有声音通知设置同一种声音。`done_path` 和 `request_path` 只覆盖完成和需要输入时的声音。

按智能体覆盖声音设置时，可使用 `default`、`on` 或 `off`。键应使用检测到的智能体标签，例如 `claude`、`codex`、`devin` 或 `droid`。Droid 默认静音。

```toml
[ui.sound.agents]
droid = "off"
claude = "on"
```

在[配置参考](/docs/config-reference/)中搜索回滚缓冲区限制、嵌套启动以及其他高级或实验性设置。启用窗格屏幕历史前，请参阅[会话状态与恢复](/docs/session-state/)；该指南说明了保存窗格内容带来的安全取舍。

## Kitty graphics

面向已连接本地客户端的 Kitty graphics 渲染是一项实验性功能，默认禁用：

```toml
[experimental]
kitty_graphics = true
```

仅在测试终端图像行为时启用。

## 智能体会话恢复

默认情况下，Shepherd 会在服务器重启后恢复受支持的智能体对话：

```toml
[session]
resume_agents_on_restore = true
```

只有通过官方集成获得有效原生会话引用的窗格才能恢复；其他窗格会作为普通 shell 恢复。有关受支持的智能体和持久化行为，请参阅[会话状态与恢复](/docs/session-state/)。

## IME 光标跟踪

在 macOS 上，隐藏硬件光标的 AI 智能体 TUI 可能导致原生输入法候选窗口无法跟随聚焦窗格。使用以下设置可为这些窗格显示光标锚点：

```toml
[experimental]
reveal_hidden_cursor_for_cjk_ime = true
cjk_ime_agents = ["claude", "pi", "codex"]
```

限制 `cjk_ime_agents` 可以避免在无关应用中额外显示硬件光标。在[配置参考](/docs/config-reference/)中搜索这些键，可查看接受的智能体名称和光标形状。

## 前缀输入源切换

在 macOS 和 Windows 上，当前缀命令和由前缀启动的模式处于活动状态时，Shepherd 可以临时切换到支持 ASCII 的输入源：

```toml
[experimental]
switch_ascii_input_source_in_prefix = true
```

在 macOS 上，会切换到当前支持 ASCII 的键盘布局；在 Windows 上，会将 IME 切换到英文（ASCII）输入。返回终端输入或进入文本字段时，Shepherd 会恢复之前的输入源。此设置在其他平台上无效。

:::caution[Windows 上仅支持韩语 IME]
目前 Windows 上的支持仅限于韩语 IME。使用其他语言的 IME 时，此设置不会改变输入源。
:::

## 环境变量

| 变量 | 用途 |
| --- | --- |
| `SHEPHERD_CONFIG_PATH` | 覆盖配置文件路径。 |
| `SHEPHERD_SESSION` | 为 CLI 命令选择命名会话。 |
| `SHEPHERD_SOCKET_PATH` | 覆盖底层 socket 路径。 |

## 日志

日志有助于诊断启动警告、集成状态或 socket API 行为。

常见日志文件：

```text
~/.config/shepherd/shepherd.log
~/.config/shepherd/shepherd-client.log
~/.config/shepherd/shepherd-server.log
```

日志会自动轮转。报告问题时，请附上当前日志和轮转后的同级日志文件。
